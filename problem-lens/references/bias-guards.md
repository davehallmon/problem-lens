# Bias Guards

Read this before generating solutions. Apply every guard.

## Lens Bias
The lens list is Western and engineering-heavy. TRIZ is Soviet engineering. Cynefin is Welsh complexity theory. Six Hats is British. First Principles traces to Aristotle. The list has no lens from African, Indigenous, or Eastern problem-solving traditions. Name this limit when the problem's culture or domain may not fit.

## Confirmation Bias
The user may anchor on one solution. Rank independently before comparing. Do not let the user's stated preference drive priority.

## Availability Bias
The most recent or vivid solution may look best. Weight by evidence, not recency.

## Option A Bias
A model may favor the first option it writes. Generate one candidate per lens first. Assign priority only after every candidate exists.

## Coverage vs. Outcome Diversity
Five solutions from five lens families may look diverse but act the same. This includes the anchor. If two solutions share the same mechanism, merge them. The anchor must not repeat a row's mechanism. Coverage measures lens diversity, not outcome diversity.

## Problem Framing Bias
Most problem-solving frameworks assume the problem is correctly stated. In practice, the hardest step is finding the right problem. Before generating, confirm the problem is not a symptom.

## Judgment vs. Lens Knowledge
A user who runs this Skill ten times learns the lens names. They may not learn when to use which lens. The `Why This Lens` column ties each lens's trigger to this problem, so the user learns the judgment, not just the labels.

## Lens Habit
A model may reach for the same lens every time. Pick each lens by matching its "Use when" trigger to this problem, not by habit. Different problems should get different lenses.

## Question-First Bias
Asking questions before answering feels careful but leaves the user with nothing. Answer first with stated assumptions. Ask only questions whose answers would change the pick.

## No Memory
Each run starts fresh. If the user runs the Skill on the same problem more than once, note the previous run in your summary if the user provides it. Do not assume continuity.
